## 本轮完成的方案设计文档

### 字幕合板.md — 行业成熟方案调研

调研了三种行业方案：
- **ffsubsync**（FFT卷积）：极快，语言无关，但只处理全局固定偏移
- **alass**（DTW+VAD）：支持分段断点和帧率差异，Rust实现
- **PluralEyes**（波形交叉相关）：商业软件，算法不公开

结论：我们的场景有两组可对比的字幕文本，不需要 VAD/ASR/波形分析。
提出了三层增强方案（FFT全局偏移 → 智能合板升级 → alass集成）。

### 智能合板完整方案.md — 完整工作流设计

**发现的核心问题**：
1. 视频素材按累加方式平铺（无间隙），不反映真实录制时间
2. 智能合板依赖字幕文本匹配，无字幕素材无法合板
3. 源时间码已提取但 MultiPointSyncService 未使用
4. 用户工作流依赖第三方字幕识别工具

**目标工作流**：
```
导入视频 → 源时间码平铺（有间隙）→ ASR识别字幕
导入音频 → 源时间码平铺 → ASR识别字幕
智能合板 → 时间码直接定位 / 字幕匹配兜底 → 清除间隙
```

**四个实施阶段**：

| 阶段 | 内容 | 改动量 | 状态 |
|------|------|--------|------|
| Phase 1 | 时间码合板：MultiPointSyncService 增加 TC 同步路径 | ~150行 | 待实施 |
| Phase 2 | 时间码平铺：视频导入时按 TC 排列，保留空白 | ~100行 | 待实施 |
| Phase 3 | whisper.cpp 集成：内置 ASR 字幕识别 | ~400行 | 待实施 |
| Phase 4 | 工作流优化：批量识别、GPU加速等 | 可选 | 待实施 |

**核心策略**：时间码能解决的不用字幕匹配，没有时间码的用字幕兜底，没有字幕的用 ASR 生成。

**文件变更计划**：
