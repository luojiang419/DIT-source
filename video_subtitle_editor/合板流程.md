# 全自动合板流程设计方案 v2.0

> 本文档为最终确认版，通过后开始执行开发。

---

## 一、核心概念

### 1.1 问题背景

影视拍摄中，摄影机和录音机**独立开机**，导致：
- 视频文件：不连续，有空镜头，有对白片段
- 音频文件：基本连续，覆盖整个拍摄时段
- 两者时间码体系不同，但**字幕内容一致**

### 1.2 关键定义

| 概念 | 说明 |
|------|------|
| 源时间码 | 24小时制绝对时间码，如 `14:32:15.480`，记录设备真实时刻 |
| 录制时间码 | 从 `00:00:00.000` 开始的相对时间码，每个文件独立计时 |
| 三段式上下文 | 以目标字幕为中心，取前一条+目标+后一条，共3条字幕作为匹配依据 |
| 偏移量 | 视频源时间码 - 音频源时间码 = 视频在音频时间轴上的位置 |

### 1.3 核心假设

1. 同一场景的视频和音频，字幕内容**完全一致或高度相似**
2. 每个媒体文件的元数据中包含**源时间码**（creation_time 或 timecode 轨道）
3. 只要找到**一对匹配字幕**，即可推算出整个文件的偏移量
4. 音频连续，视频不连续（有空镜头间隔）

## 三、详细算法设计

### 3.1 阶段一：三段式上下文匹配

#### 输入
- 视频字幕列表（来自视频轨道的 `linkedSubtitleTrack`）
- 音频字幕列表（来自音频轨道的 `linkedSubtitleTrack`）

#### 算法步骤

```
1. 对视频字幕列表，以每条字幕为中心，构建三段式上下文：
   Context = { prev: 上一条, target: 当前条, next: 下一条 }

2. 对音频字幕列表，同样构建三段式上下文列表

3. 遍历所有视频上下文，在音频上下文中寻找匹配：
   匹配条件：三条字幕的文本内容相似度 >= 90%

4. 返回所有匹配对，按置信度排序
```

#### 示例

```
视频字幕：
  [0] "你是谁"      00:00:05 - 00:00:07
  [1] "不告诉你"    00:00:10 - 00:00:12   ← 目标
  [2] "别管我"      00:00:15 - 00:00:17

视频上下文[1] = { prev:"你是谁", target:"不告诉你", next:"别管我" }

音频字幕：
  [45] "你是谁"     00:12:05 - 00:12:07
  [46] "不告诉你"   00:12:10 - 00:12:12   ← 匹配
  [47] "别管我"     00:12:15 - 00:12:17

音频上下文[46] = { prev:"你是谁", target:"不告诉你", next:"别管我" }

→ 匹配成功，置信度 100%
```

### 3.2 阶段二：源时间码读取与偏移量计算

#### 3.2.1 源时间码读取（FFprobe）

使用 FFprobe 读取文件元数据，按优先级尝试以下字段：

```
优先级1：format_tags.creation_time（ISO 8601格式，如 2024-03-15T14:32:15.480000Z）
优先级2：stream_tags.timecode（SMPTE格式，如 14:32:15:12）
优先级3：format_tags.com.apple.quicktime.creationdate
优先级4：文件修改时间（最后兜底）
```

FFprobe 命令：
```bash
ffprobe -v error \
  -show_entries format_tags=creation_time \
  -show_entries stream_tags=timecode \
  -of json \
  input.mp4
```

#### 3.2.2 偏移量计算公式

```
已知：
  - 视频文件 V 的源起始时间码：V_source_start（毫秒）
  - 音频文件 A 的源起始时间码：A_source_start（毫秒）
  - 匹配字幕在视频录制时间轴的位置：V_subtitle_recording（毫秒）
  - 匹配字幕在音频录制时间轴的位置：A_subtitle_recording（毫秒）

计算：
  V_subtitle_source = V_source_start + V_subtitle_recording  （字幕在源时间轴的绝对位置）
  A_subtitle_source = A_source_start + A_subtitle_recording  （字幕在源时间轴的绝对位置）

  offset = V_subtitle_source - A_subtitle_source
         = (V_source_start + V_subtitle_recording) - (A_source_start + A_subtitle_recording)

视频片段在音频时间轴上的位置：
  video_position_on_audio = V_source_start - A_source_start
                          = offset - V_subtitle_recording + A_subtitle_recording
```

#### 3.2.3 多视频文件处理

每个视频文件独立计算其在音频时间轴上的位置：

```
对于视频文件 Vi：
  position_i = Vi_source_start - A_source_start

这样，无论视频是否连续拍摄，都能正确定位到音频时间轴上。
```

#### 3.2.4 示例

```
音频文件 A.wav：
  源起始时间码：14:00:00.000（50400000ms）

视频文件 V1.mp4（说了"你是谁"）：
  源起始时间码：14:10:00.000（50400000 + 600000 = 51000000ms）
  → 在音频时间轴位置：51000000 - 50400000 = 600000ms（10分钟处）

视频文件 V2.mp4（空镜头）：
  源起始时间码：14:15:00.000
  → 在音频时间轴位置：900000ms（15分钟处）

视频文件 V3.mp4（空镜头）：
  源起始时间码：14:18:00.000
  → 在音频时间轴位置：1080000ms（18分钟处）

视频文件 V4.mp4（说了"不告诉你"）：
  源起始时间码：14:25:00.000
  → 在音频时间轴位置：1500000ms（25分钟处）

结果：视频按源时间码平铺到音频轨道，中间留白可见
```

### 3.4 阶段四：一键修剪

#### 修剪前状态（合板后）

```
视频轨道: [V1 5min]    [V2 3min]    [V4 5min]
          10:00        15:00        25:00
          ↑            ↑            ↑
          10分钟空白    3分钟空白    5分钟空白

音频轨道: [▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓] 连续
```

#### 修剪步骤

```
步骤1：按视频片段范围裁切音频
  → 音频A段：对应V1时间范围（10:00 - 15:00）
  → 音频B段：对应V2时间范围（15:00 - 18:00）
  → 音频C段：对应V4时间范围（25:00 - 30:00）

步骤2：计算压缩偏移量（消除视频间空白）
  → V1：位置 10:00 → 压缩到 00:00（偏移 -10:00）
  → V2：位置 15:00 → 压缩到 05:00（偏移 -10:00）
  → V4：位置 25:00 → 压缩到 08:00（偏移 -17:00，消除了V2后的空白）

步骤3：应用压缩到所有轨道
  → 视频片段移动到新位置
  → 音频段落跟随视频移动
  → 字幕跟随对应媒体移动
```

#### 修剪后状态

```
视频轨道: [V1 5min][V2 3min][V4 5min]
          00:00    05:00    08:00
          无缝连接，无空白

音频轨道: [▓▓▓▓▓][▓▓▓][▓▓▓▓▓]
          00:00   05:00 08:00
          三段，与视频完全对齐

字幕：    [你是谁][空镜][不告诉你]
          00:00   05:00 08:00

总时长：13分钟（原来35分钟，清理了22分钟空白）
```

## 五、数据模型变更

### 5.1 新增模型

#### `SourceTimecode`（源时间码）
```dart
class SourceTimecode {
  final String filePath;
  final int startMs;    // 源起始时间码（毫秒，24h制）
  final int durationMs; // 文件录制时长

  // 录制时间码 → 源时间码
  int toSource(int recordingMs) => startMs + recordingMs;
  // 源时间码 → 录制时间码
  int toRecording(int sourceMs) => sourceMs - startMs;
}
```

#### `SubtitleContext`（三段式上下文）
```dart
class SubtitleContext {
  final TimelineClip? prev;
  final TimelineClip target;
  final TimelineClip? next;
  final String filePath;  // 所属文件

  String get fingerprint =>
    '${_normalize(prev?.text)}|${_normalize(target.text)}|${_normalize(next?.text)}';
}
```

#### `SyncMatch`（匹配结果）
```dart
class SyncMatch {
  final SubtitleContext videoContext;
  final SubtitleContext audioContext;
  final double confidence;  // 0.0 - 1.0
}
```

#### `CompactInfo`（压缩信息，用于修剪后记录）
```dart
class CompactInfo {
  final int totalGapRemovedMs;
  final Map<String, int> clipOffsets; // clipId → 压缩偏移量
}
```

## 七、边界情况处理

| 情况 | 处理方式 |
|------|----------|
| 视频或音频没有字幕 | 提示"请先为视频和音频导入字幕" |
| 找不到匹配的上下文 | 提示"未找到匹配字幕，请检查字幕内容是否一致" |
| 找到多处匹配 | 弹出选择对话框，让用户选择正确的匹配对 |
| 源时间码读取失败 | 提示"无法读取源时间码，请确认文件包含时间码元数据" |
| 视频时间码早于音频 | 支持负偏移量，视频位置在音频起点之前（显示为0处） |
| 音频横跨多个视频 | 按每个视频的时间范围分别裁切音频段落 |

## 十、技术难点与解决方案

### 10.1 模糊匹配算法

字幕可能存在标点差异、空格差异、轻微识别误差，不能只做精确匹配。

**处理步骤：**
```
1. 预处理：去除标点符号、统一全半角、去除多余空格
   "你好，世界！" → "你好世界"

2. 计算 Levenshtein 编辑距离
   相似度 = 1 - (编辑距离 / max(len_a, len_b))

3. 阈值：单条字幕相似度 >= 85%，三条上下文平均 >= 90%

4. 置信度计算：
   - 三条完全匹配 → 100%
   - 两条完全匹配 + 一条模糊匹配 → 85%
   - 一条完全匹配 + 两条模糊匹配 → 70%（需用户确认）
```

### 10.2 源时间码格式兼容

不同设备输出的时间码格式不同，需要统一解析为毫秒：

| 格式 | 示例 | 来源设备 |
|------|------|----------|
| ISO 8601 | `2024-03-15T14:32:15.480000Z` | 大多数相机 |
| SMPTE | `14:32:15:12`（最后是帧号） | 专业摄影机 |
| QuickTime | `2024-03-15 14:32:15` | Apple 设备 |
| 文件修改时间 | 系统时间戳 | 兜底方案 |

**SMPTE 帧号转毫秒：**
```
帧率 = 从视频流读取（如 24fps、25fps、29.97fps）
毫秒 = 帧号 / 帧率 * 1000
```

### 10.3 多音频轨道处理

项目中可能有多条音频轨道（如多个录音机），每条音频独立计算偏移量：

```
对于每条音频轨道 Ai：
  1. 读取 Ai 的源时间码
  2. 在 Ai 的字幕中查找与视频匹配的上下文
  3. 计算 Ai 相对视频的偏移量
  4. 独立应用偏移量，互不影响
```

### 10.4 字幕跟随机制

字幕通过 `linkedSubtitleTrack` 绑定到媒体轨道，移动媒体时字幕同步移动：

```
合板阶段：
  视频片段整体偏移 Δt → 视频字幕整体偏移 Δt

修剪阶段：
  1. 找到字幕所属的视频/音频片段（按时间范围判断）
  2. 字幕跟随对应片段移动到压缩后的新位置
  3. 超出片段范围的字幕丢弃（不应出现此情况）

核对方式：
  同一时间点，视频字幕和音频字幕内容应一致 → 对齐正确
```

### 10.5 源时间码读取失败的降级策略

```
降级顺序：
  1. FFprobe 读取 creation_time → 成功则使用
  2. FFprobe 读取 timecode 轨道 → 成功则使用
  3. 读取文件修改时间 → 作为近似值使用，提示用户精度可能有偏差
  4. 全部失败 → 提示用户手动输入偏移量（秒），转为手动合板模式
```

## 十一、与现有功能的集成关系

### 现有"一键对齐"功能 vs 新"一键合板"功能

| 对比项 | 现有一键对齐 | 新一键合板 |
|--------|------------|-----------|
| 触发方式 | 用户手动输入关键词 | 全自动，无需输入 |
| 匹配依据 | 单条字幕精确匹配 | 三段式上下文匹配 |
| 偏移计算 | 基于字幕时间码差值 | 基于源时间码（24h制） |
| 适用场景 | 视频和音频同时开机 | 视频和音频独立开机 |
| 结果 | 当前项目内对齐 | 新建合板标签页 |
| 空镜头处理 | 不处理 | 保留留白，可见开关机时间 |

两个功能**并存**，用户根据实际情况选择使用。
